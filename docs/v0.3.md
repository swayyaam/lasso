# Lasso 0.3 — the plan

0.2 made starting a download pleasant. 0.3 makes a download something you can
leave alone, and brings Lasso to Windows. Tick items as they land. A phase is
done when `make test` and `make lint` pass and it is pushed.

**The theme:** leave it running, on either platform.

Order matters. Phases 1 to 3 make the Mac app better and ship on their own.
Phase 4 is refactoring with no visible change, so the Mac app keeps working
while the Windows work lands on top of it.

---

## Phase 1 — Leave it running

None of these is handled today; each was checked in the code, not assumed.
Shipped early, as 0.2.2 (2026-09-26); the release build was checked holding
the assertion while downloading and letting it go on quit.

- [x] **Keep the Mac awake while anything downloads.** A power assertion,
      "Lasso is downloading", held while any download is working (paused ones
      do not count) and released when none is. Idle sleep only: the display
      still sleeps, and a closed lid on battery still sleeps the Mac. Tested
      against `pmset -g assertions`, which lists it while held and not after.
- [x] **Retry network drops by themselves.** A dropped connection waits 10 s,
      30 s, then 2 min, resuming from the part file each time; the card shows
      "Connection lost. Try 1 of 3 · trying again in 8 s" with the bar
      greyed. Pause and Cancel work during the wait. Only network failures
      are retried. It also fixed a path where retrying after dropped subtitles
      would have asked for the subtitles again. *Not yet seen live:* pulling
      the network mid-download on a real machine.
- [x] **One-click fix for a stale yt-dlp.** A new `site-changed` kind, keyed
      on yt-dlp's own "please report this issue" wording (verbatim from its
      source), offers "Update yt-dlp and retry" on the failed download and on
      its playlist. If yt-dlp is already the newest, it says the fix has to
      come from yt-dlp. The doctor shows yt-dlp's version and age, and past 60
      days offers "Update yt-dlp" itself.

## Phase 2 — Clips, dark mode, and what 0.2 left

- [x] **Dark mode** (shipped in 0.2.3). Settings › Appearance: Light, Dark, or
      Auto, which follows the Mac and is the default. The dark palette is the
      design document's polarity flip applied to every token, derived by
      measurement (the method is in `tokens.css`) and checked against WCAG AA
      on every screen in the running app: no text below 4.5:1. The window's
      chrome and background follow the setting from the first frame. It also
      fixed the window's background alpha, which was 1 of 255 rather than
      opaque.
- [x] **A new icon and mark** (shipped in 0.2.3). The five accents as one
      ring, on a near-black tile for the icon and alone in the title bar.
      Drawn from geometry by `scripts/icon` (`make icon`), so it is sharp at
      every size and its colours are the tokens; a thicker band carries 16 and
      32 px.
- [ ] **Clips.** Choose takes an optional start and end time; the download is
      `--download-sections "*start-end"` with `--force-keyframes-at-cuts` so
      the cut lands where asked. The size estimate scales with the clip. The
      history line says "Clip 1:00–2:30".
- [ ] **One total per download.** The card counts to 71 MB for the video
      stream and then starts again for the audio. Show the whole download's
      size and progress across its streams.
- [ ] **Offer the doctor when a link fails to resolve.** The error crosses to
      the page as a string today, so Choose cannot tell a bot check from a typo.
      Return the error kind with it.
- [ ] **Smaller download.** Thin yt-dlp's universal binaries to arm64: the
      bundle drops from 328 MB to 271 MB (measured; CLAUDE.md, "Deferred:
      distribution"). Every thinned image is re-signed.
- [ ] **Look at what 0.2's check could not:** the Dock badge, and a link
      dropped on the Dock icon.

## Phase 3 — Music at the source's best

Lasso cannot deliver more than a site sends, and to a signed-out visitor the
big sites send little. Measured on 2026-09-23:

| Source | Best stream, signed out |
|---|---|
| YouTube | Opus about 129 kbps, AAC about 130 kbps |
| SoundCloud | MP3 128 kbps, AAC 96 kbps |

Converting either to a 320 kbps MP3 gives a file 2.5 times bigger with the
same sound, or slightly worse, since it is a second lossy encode. It is the
FLAC trap again (CLAUDE.md, "Audio quality"). So this phase is about getting
the best real stream, saying what it is, and making the file a proper music
file.

- [ ] **Show the real quality.** Choose says what Original is before the
      download ("Original · Opus 129 kbps"), from the best audio stream's
      codec and bitrate. The finished file says what arrived, recorded from
      yt-dlp's own report the way resolution is (`%(acodec)s`, `%(abr)s`), in
      the downloads list and in history.
- [ ] **Say when better quality exists.** YouTube Premium serves a 256 kbps
      stream, and SoundCloud Go+ a 256 kbps AAC one, both reachable through
      cookies from a signed-in browser; Original already picks the highest
      bitrate it is offered. When a source caps out around 128 kbps and an
      account would unlock more, the Audio card says so and points at cookies.
      *Verify both with real Premium and Go+ accounts before the interface
      promises them.*
- [ ] **Tags and cover art by default for audio.** A SoundCloud track arrived
      as a bare MP3, with no artist, title or artwork, because embedding is off
      unless turned on. Audio downloads embed metadata and the thumbnail as
      artwork by default, with a setting to turn it off. Check every audio
      format, Opus included, which needs mutagen inside yt-dlp's build.
- [ ] **Sets and albums from audio-only sites open on Audio.** A playlist's
      videos are not looked up before Choose, so every playlist gets the video
      ladder and a SoundCloud set opens on Video. The flat playlist names its
      extractor (`SoundcloudSet`, entries `Soundcloud`): known audio-only
      sites (SoundCloud, Bandcamp, Mixcloud, Audiomack) open on Audio with the
      Video card off.
- [ ] **Real track names in a set.** SoundCloud's flat set lists links with
      no titles or lengths, so the list to tick shows URLs. Look up the names
      for sets of a reasonable size before showing the list, and fall back to
      a name made from the link's last part ("world-on-fire-1" becomes "World
      on fire 1").
- [ ] **Add to Music.** An option (Settings, and per download on Choose for
      audio) to hand finished audio to the Music app through its "Automatically
      Add to Music" folder. Off by default; the file stays in the download
      folder too.

## Phase 4 — Seams for a second platform

No visible change: the Mac app must behave exactly as before.

- [ ] **Tests on Windows in CI.** A GitHub Actions workflow runs every Go
      module's tests on `windows-latest` and `macos-latest` on each push. It is
      the only Windows machine this project has until a person runs the app,
      so it goes first.
- [ ] **Stopping a download.** `core/runner.go` kills a Unix process group
      (`Setpgid`, signal to `-pid`). Windows has no process groups: yt-dlp and
      the ffmpeg it starts go into a job object with kill-on-close. Split into
      `runner_unix.go` and `runner_windows.go`, with the orphan test running on
      both.
- [ ] **Helper programs.** `binaries` strips quarantine (`xattr`) and fixes
      signatures (`codesign`), which exist only on the Mac. Behind a
      per-platform `fixup`; on Windows it removes the downloaded-file mark
      (`Zone.Identifier`) instead. `binaries.lock.json` gains Windows
      artifacts: `yt-dlp_win.zip` (the same onedir layout), ffmpeg and ffprobe
      from a pinned GPL win64 build (BtbN), and deno's
      `x86_64-pc-windows-msvc` zip. Every one is pinned by checksum, as now.
- [ ] **Paths.** The support folder is `%APPDATA%\Lasso`; the default
      download folder is the user's Downloads. `LASSO_SUPPORT_DIR` works the
      same on both.
- [ ] **What "Best" plays.** `core.Playback` is already a plain value;
      Windows fills it from Media Foundation (`MFTEnumEx` for an AV1 or HEVC
      decoder) the way the Mac asks VideoToolbox. H.264 and AAC in MP4 play
      everywhere, so that stays the floor.

## Phase 5 — Lasso on Windows

Every `_darwin.go` gets a `_windows.go` beside it. Wails runs on WebView2,
which Windows 10 and 11 ship.

- [ ] **Window.** The native Windows title bar, not the Mac's inset traffic
      lights, so snapping and the system buttons behave as Windows users
      expect. The title bar component drops its traffic-light padding there.
- [ ] **Shortcuts and menus.** Ctrl where the Mac has ⌘, and the keyboard
      table in the README says both. Windows has no menu bar across the top of
      the screen: Settings and History stay in the title bar, and the
      shortcuts work without a menu.
- [ ] **One copy at a time.** `LockFileEx` on the same `lasso.lock`; a second
      copy brings the first forward and exits.
- [ ] **Notifications** as Windows toasts, under Lasso's name.
- [ ] **Show in Explorer** (`explorer /select,`), and open with the default
      app.
- [ ] **Free space** through `GetDiskFreeSpaceEx`.
- [ ] **The taskbar** shows progress and the unfinished count, as the Dock
      badge does.
- [ ] **Links from outside.** `lasso://` registered for the user
      (`HKCU\Software\Classes\lasso`), `.url` shortcuts opened with Lasso, and
      drops on the window as now. `core.IncomingLink` applies unchanged.
- [ ] **Cookies.** Firefox works. Chrome and Edge since 2024 encrypt cookies
      with a key tied to the browser itself (App-Bound Encryption), which
      yt-dlp cannot read. Settings says so plainly instead of offering a choice
      that will fail. Verify against the yt-dlp version pinned then.
- [ ] **The doctor** checks what applies on Windows and skips the rest.

## Phase 6 — Shipping two platforms

- [ ] **An installer.** A per-user installer (Wails' NSIS target, no admin
      prompt) that adds a Start menu entry and registers `lasso://`. Built
      from the Mac by cross-compiling, which Wails supports for Windows.
- [ ] **Updating in place.** A running .exe cannot be replaced, so the
      updater stages the new files, starts a small swap step, and exits. The
      same rules as the Mac: verify before touching anything, keep the old copy
      until the new one runs.
- [ ] **One `latest.json` for both.** Old Mac copies look up
      `assets["Lasso-app.zip"]` and ignore other keys, so Windows files are
      added under their own names and nothing a 0.1.6 or 0.2 copy reads
      changes. A test pins that.
- [ ] **SmartScreen.** An unsigned Windows app is stopped by "Windows
      protected your PC" (More info → Run anyway), the same position the Mac
      app is in with Gatekeeper. The README says so. Code signing is a later
      decision, as on the Mac.
- [ ] **CLAUDE.md** gains the Windows rules the way it has the Mac ones.

## Phase 7 — Ship 0.3.0

- [ ] End-to-end on the Mac, as for 0.2.
- [ ] End-to-end on a real Windows PC: install, first run, every screen, a
      download, cancel (no orphaned ffmpeg in Task Manager), a `lasso://` link,
      an update from a staged older build, uninstall. *Needs a person with a
      Windows machine*: nothing here can run Windows beyond CI's tests.
- [ ] README for both platforms.
- [ ] Release with the staged process, both platforms' files, both discovery
      paths checked.

## Decisions

- **Adopted:** Windows support (2026-09-23). CLAUDE.md's "Target is macOS
  only" changes to match.
- **Defaults, unless you say otherwise:**
  - Windows x64 first; arm64 later (yt-dlp publishes it, the rest may not).
  - A per-user installer rather than a portable .exe, because `lasso://` and
    the Start menu need registering.
  - The native title bar on Windows.
  - No code signing on Windows either, for now.
- **Open: 320 kbps MP3.** Only as an explicit output, labelled honestly
  ("same sound as the 129 kbps source, in a bigger file"), and only if it is
  needed for a device or app that insists on 320 kbps MP3s. It does not
  improve the sound. Waiting on what the 320 is for.
- **Carried from 0.2, still skipped:** signed Lasso releases, an Intel Mac
  build, notarisation. Recording live streams is later.

# Lasso 0.2 — the plan

Everything found since 0.1 in one place: the security audit, the functional
gaps, the UX deep dive and the research into what comparable apps do. Each item
says what is wrong, where, and how we will know it is fixed. Tick items as they
land; a phase is done when `make test` and `make lint` pass and it is pushed.

**The theme:** YouTube keeps working, links come from anywhere, nothing gets
lost — and the app looks like it means it.

Proposed UI: https://claude.ai/artifact/S4yznXtQwmbS1kbieVVvSx (three screens,
in the app's own tokens; the middle one is clickable).

---

## Phase 1 — Security hardening

Nothing found lets a site or a link run code. These close the gaps that remain.

- [x] **S1 Thumbnail image bomb crashes the app from a pasted link.** The 10 MB
      cap bounds bytes read, not pixels decoded; measured ~850× expansion at
      8000², rising with size. yt-dlp's generic extractor makes any page's
      `og:image` a thumbnail. `packages/core/thumbnails.go` (`image.Decode`).
      *Done when:* dimensions are read with `image.DecodeConfig` first and
      anything over a pixel budget is refused before allocation; a test feeds a
      header claiming huge dimensions and nothing large is allocated.
- [x] **S3 SSRF guard misses non-public ranges.** Measured passing as "public":
      `100.64.0.0/10` (CGNAT — every Tailscale peer), `0.0.0.0/8`,
      `198.18.0.0/15`, NAT64 `64:ff9b::/96`. `isPublicIP` in
      `packages/core/thumbnails.go`. *Done when:* an explicit deny list of
      prefixes (plus 240/4, 6to4 and Teredo wrapping private v4) is tested
      address by address.
- [x] **S5 yt-dlp's default plugin folders are live.** `--ignore-config` does not
      clear them; a plugin installed for CLI use would run inside every Lasso
      download. *Done when:* every yt-dlp invocation passes `--no-plugin-dirs`
      (Lasso's own plugins, if any, come back with an explicit `--plugin-dirs`).
- [x] **S6 `OpenFile` / `RevealInFinder` open any path the webview passes.**
      *Done when:* they take a queue or history ID and resolve the path
      themselves; bindings regenerated.
- [x] **S7 `Output.Folder` from the webview is honoured unvalidated.**
      *Done when:* only the Settings folder or one the user picked in the
      native dialog is accepted.
- [x] **S8 No Content-Security-Policy.** The rule "the webview never talks to a
      CDN" holds by convention only. *Done when:* a CSP in `index.html` makes it
      mechanical, and the app still loads its thumbnails and fonts.

## Phase 2 — Things that are wrong, not just ugly

- [x] **"Best quality" can produce a file macOS cannot play.** archive.org's Big
      Buck Bunny came down as a 317 MB MPEG-4 Part 2 AVI; AVFoundation reports
      `isPlayable=false`, so QuickTime, Quick Look and Photos refuse it. *Done
      when:* "Best" means the best that plays on this Mac — preferring
      H.264/HEVC/AV1 and AAC in MP4 where available, and saying plainly when the
      top quality (e.g. VP9 4K) needs another player — with "Original file" as
      an explicit choice.
- [x] **Audio sizes are the source stream's size for every format.** FLAC, MP3
      and Original all showed 309 KB. *Done when:* each format's estimate comes
      from its own bitrate × duration, and FLAC says it is bigger, not better.
- [x] **Errors misdiagnosed.** A 404 said "check your internet connection" while
      a download ran at 4.5 MB/s beside it. YouTube's bot check says the video
      "requires you to be signed in". *Done when:* 404/410/403 and the bot check
      are their own kinds with honest wording and a fix where there is one, each
      tested against verbatim yt-dlp output.
- [x] **Doctor summary shows a warning with a green success tick.**
- [x] **29 text uses of greys that fail WCAG AA** (`ink-tertiary` 3.5:1,
      `ink-faint` 2.3:1; AA needs 4.5:1 under 24 px).
- [x] **A second press of Download queued an identical copy.** The composer
      keeps the link on purpose (the same link at another quality is a real
      want); the queue now refuses the *same* download while one is running.
      Found on the way: its refusal was headed "That link did not work", so
      composer errors are now titled by the action that failed.

## Phase 3 — Nothing gets lost

- [x] **Single instance.** Two copies share one settings file and clobber it.
- [x] **The queue survives quitting, crashing and restarting**, including paused
      and failed items; unfinished downloads resume with `--continue`.
- [x] **Live streams are detected** (`live_status`) and not started as a
      download: live, not-yet-started and just-ended streams say why, and the
      recording downloads like any video once the stream is over. They used to
      record until the disk filled.
- [ ] **Record live streams** — later (decided 2026-09-23). Two things block
      doing it properly: nothing yt-dlp reports tells a stream that will end
      from a 24/7 one (neither has a duration), and Cancel kills yt-dlp
      outright, which leaves a part file rather than a playable recording. A
      real version needs a graceful stop and a size or time limit the user
      sets.
- [x] **A playlist becomes real rows.** Today 183 videos are one row: one
      progress bar resetting 183 times, no per-video retry or cancel, serial
      despite "Downloads at once", one history entry, Show in Finder pointing at
      the last file. The flat entry list is already fetched.

## Phase 4 — YouTube keeps working

- [ ] **Proof-of-Origin tokens — measured, deferred.** bgutil 2.0.0 works with
      Lasso's own yt-dlp and deno (`--plugin-dirs` after `--no-plugin-dirs`,
      script mode, "Retrieved a gvs PO Token"). Against it:
      - From an unflagged network it changed nothing: the same 53 formats up to
        2160p with and without it. It cost 4 s on every resolve (7 s vs 3 s).
      - Its install is 328 MB with 39 native images (canvas, swc), which would
        double the bundle. `deno bundle` gets `generate_once.ts` to one 15 MB
        file, but jsdom then reads `default-stylesheet.css` via `__dirname` and
        dies. That is fixable by inlining the file, at the cost of a build step
        that has to track upstream.
      - It is pinned code chasing YouTube's changes, and it would not update with
        yt-dlp.
      - The "done when" (success from a flagged network) cannot be shown here.

      Revisit if bot checks become common with cookies on. The slim path is the
      15 MB bundle plus the stylesheet inlined, with Lasso passing
      `XDG_CACHE_HOME` so its cache lands in the support folder rather than
      `~/.cache`.
- [x] **Bot check as a doctor check.** `doctor.BotChecks` remembers YouTube
      refusing this connection, fed by every resolve and finished download, and
      forgets it when YouTube next works. The doctor then shows a YouTube line:
      - with no cookies: fail, "choose a browser you're signed in to"
      - with unreadable cookies: fail, "fix the cookie problem above first"
      - with working cookies: warn, "the block is on this connection"

      There is no standing line when nothing was refused, because the doctor
      does not ask YouTube. The composer cannot offer the doctor on a resolve
      failure (the error crosses as a string); that belongs to Phase 5's
      composer.

## Phase 5 — The redesign

The UX audit's diagnosis: Lasso kept Webflow's restraint and dropped its
boldness — the largest type in the app is 20 px and colour appears only as
6 px dots. The proposal uses more of `DESIGN-webflow.md`, not less.

- [x] Display type tokens: `text-display` (display-md, 32 px) and
      `text-heading` (display-sm, 24 px), at the document's weights and zero
      tracking. Ready, History and Settings lead with one; Choose leads with the
      video's title. Downloading keeps the mockup's eyebrows.
- [x] **Ready:** one job on screen — paste — with the last five downloads and
      their thumbnails below it.
- [x] **Choose:** Video and Audio as full-colour category cards; one quality
      list with a size on every row ("about" where it is an estimate); "Saved
      choices" as a menu, with renaming and deleting in Settings; the button
      says what you get ("Download · 723 MB", "Download 2 videos"). A playlist
      lists its videos to tick, which replaces the drawer's range fields. More
      options is a sheet, and the yt-dlp command is at the foot of it.
- [x] **Downloading:** the running download as a card with size, speed and
      time left; a playlist as one card with its own progress; failures in
      "Needs attention" with Retry and, where it helps, Diagnose; Open and Show
      in Finder labelled. The title bar says "2 downloading" while you are
      looking at something else.
- [x] **History:** thumbnails, dates ("Today", "Sep 19"), and search over the
      title, the channel, the link and the file ("4K", "mp3").
- [x] **Settings:** Preferences, and About & diagnostics; helper versions
      folded away; the doctor row renamed so it does not repeat its heading.
      Dropdowns show their empty option's own label ("None", "Automatic")
      rather than "Select".
- [x] Jargon pass: no format count, no raw "best" or "480p" as a description,
      no yt-dlp version in the title bar. A finished file is described by what
      it is ("Video · 4K MP4 · 723 MB"), which needed the backend to report the
      real resolution (short side, so a Short is 1080p) and the size on disk.
- [x] CLAUDE.md's "Two-pane window" and "Compressed density" replaced.

Found on the way, both in 0.1.x:

- [x] **8K, 480p and 360p downloaded as Best.** The quality list offered every
      rung of the ladder, but the arg builder only knew four of them; the rest
      carried no height cap. A 38 MB 480p pick arrived as 712 MB of 4K. The cap
      is now read off the same ladder, `Validate` refuses a pick it does not
      know, and a test walks every offered rung.
- [x] **A second quality of the same video silently returned the first.** Both
      had the same filename, so yt-dlp skipped the download as already done. A
      resolution pick now carries its rung in the default name ("… 480p.mp4"),
      and a genuine repeat says "You already had this file".

## Phase 6 — Links from anywhere

- [x] Drop a link on the window: an overlay says it will open, and every drop
      is cancelled so the webview never navigates away. On the Dock icon: web
      links, `.webloc` and `.url` are declared at Alternate rank, and arrive
      through `OnUrlOpen` and `OnFileOpen`.
- [x] `lasso://open?url=…`, so a bookmarklet or Shortcut can hand Lasso a URL.
      Held to `core.IncomingLink`: http(s) only, never a local address. A link
      that launches Lasso waits to be collected rather than being lost.
- [x] A real menu bar: Lasso › Settings… ⌘,; File › Paste Link ⌘⇧V and
      Download ⌘↩; View › Downloads ⌘1 and History ⌘Y; Edit and Window as
      before.
- [x] Dock badge with the number of unfinished downloads.

## Phase 7 — Trust and reach

- [ ] **Signed releases — not in 0.2** (decided 2026-09-23). Every install is
      still protected only by the GitHub account. Signing `latest.json` with
      ed25519 and embedding the public key, as Sparkle does, remains the plan
      when there is somewhere to keep the private key.
- [x] **Verify yt-dlp's own signature.** `SHA2-256SUMS.sig` must verify
      against yt-dlp's release key (embedded, fingerprint-pinned) before the
      archive is fetched. Checked offline against the real 2026.08.19 pair and
      live by the integration update.
- [ ] **Intel Macs — not in 0.2** (decided 2026-09-23). Lasso stays arm64
      only; a universal build or a separate Intel download is for later.

## Phase 8 — Ship 0.2.0

- [x] End-to-end pass in the real app. In the dev lab against real sites, then
      in the 0.2.0 release build itself: Ready, Choose, Downloading, Finished,
      History and Settings, and ⌘Y, ⌘, and File › Download from the real menu.
      `lasso://` and `.webloc` arrive through Apple Events. The pass caught the
      wordmark touching the traffic lights, fixed before release. Not checked
      by eye: the Dock badge and a drop on the Dock icon.
- [x] README updated for the new flow.
- [x] Released 0.2.0 on 2026-09-23: staged publish, every asset downloaded
      back and verified before going public, both discovery paths checked.

## Decisions

- **Adopted:** the redesign direction in the mockup, which replaces CLAUDE.md's
  "Two-pane window" and "Compressed density" rules (Phase 5).
- **Not in 0.2** (2026-09-23): signed releases, an Intel build, and
  notarisation, which needs the paid Apple Developer Program. Recording live
  streams is later.

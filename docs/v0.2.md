# Lasso 0.2 — the plan

Everything found since 0.1 in one place: the security audit, the functional
gaps, the UX deep dive and the research into what comparable apps do. Each item
says what is wrong, where, and how we will know it is fixed. Tick items as they
land; a phase is done when `make test` and `make lint` pass and it is pushed.

**The theme:** YouTube keeps working, links come from anywhere, nothing gets
lost — and the app looks like it means it.

Proposed UI: https://claude.ai/artifact/S4yznXtQwmbS1kbieVVvSx (three screens,
in the app's own tokens; the middle one is clickable).

## Phase 1 — Security hardening

Nothing found lets a site or a link run code. These close the gaps that remain.

- [x] **S1 Thumbnail image bomb crashes the app from a pasted link.** The 10 MB
      cap bounds bytes read, not pixels decoded; measured ~850× expansion at
      8000², rising with size. yt-dlp's generic extractor makes any page's
      `og:image` a thumbnail. `packages/core/thumbnails.go` (`image.Decode`).
      *Done when:* dimensions are read with `image.DecodeConfig` first and
      anything over a pixel budget is refused before allocation; a test feeds a
      header claiming huge dimensions and nothing large is allocated.
- [x] **S3 SSRF guard misses non-public ranges.** Measured passing as "public":
      `100.64.0.0/10` (CGNAT — every Tailscale peer), `0.0.0.0/8`,
      `198.18.0.0/15`, NAT64 `64:ff9b::/96`. `isPublicIP` in
      `packages/core/thumbnails.go`. *Done when:* an explicit deny list of
      prefixes (plus 240/4, 6to4 and Teredo wrapping private v4) is tested
      address by address.
- [x] **S5 yt-dlp's default plugin folders are live.** `--ignore-config` does not
      clear them; a plugin installed for CLI use would run inside every Lasso
      download. *Done when:* every yt-dlp invocation passes `--no-plugin-dirs`
      (Lasso's own plugins, if any, come back with an explicit `--plugin-dirs`).
- [x] **S6 `OpenFile` / `RevealInFinder` open any path the webview passes.**
      *Done when:* they take a queue or history ID and resolve the path
      themselves; bindings regenerated.
- [x] **S7 `Output.Folder` from the webview is honoured unvalidated.**
      *Done when:* only the Settings folder or one the user picked in the
      native dialog is accepted.
- [x] **S8 No Content-Security-Policy.** The rule "the webview never talks to a
      CDN" holds by convention only. *Done when:* a CSP in `index.html` makes it
      mechanical, and the app still loads its thumbnails and fonts.

## Phase 2 — Things that are wrong, not just ugly

- [x] **"Best quality" can produce a file macOS cannot play.** archive.org's Big
      Buck Bunny came down as a 317 MB MPEG-4 Part 2 AVI; AVFoundation reports
      `isPlayable=false`, so QuickTime, Quick Look and Photos refuse it. *Done
      when:* "Best" means the best that plays on this Mac — preferring
      H.264/HEVC/AV1 and AAC in MP4 where available, and saying plainly when the
      top quality (e.g. VP9 4K) needs another player — with "Original file" as
      an explicit choice.
- [x] **Audio sizes are the source stream's size for every format.** FLAC, MP3
      and Original all showed 309 KB. *Done when:* each format's estimate comes
      from its own bitrate × duration, and FLAC says it is bigger, not better.
- [x] **Errors misdiagnosed.** A 404 said "check your internet connection" while
      a download ran at 4.5 MB/s beside it. YouTube's bot check says the video
      "requires you to be signed in". *Done when:* 404/410/403 and the bot check
      are their own kinds with honest wording and a fix where there is one, each
      tested against verbatim yt-dlp output.
- [x] **Doctor summary shows a warning with a green success tick.**
- [x] **29 text uses of greys that fail WCAG AA** (`ink-tertiary` 3.5:1,
      `ink-faint` 2.3:1; AA needs 4.5:1 under 24 px).
- [x] **A second press of Download queued an identical copy.** The composer
      keeps the link on purpose (the same link at another quality is a real
      want); the queue now refuses the *same* download while one is running.
      Found on the way: its refusal was headed "That link did not work", so
      composer errors are now titled by the action that failed.

## Phase 3 — Nothing gets lost

- [ ] **Single instance.** Two copies share one settings file and clobber it.
- [ ] **The queue survives quitting, crashing and restarting**, including paused
      and failed items; unfinished downloads resume with `--continue`.
- [ ] **Live streams are detected** (`live_status`): say so, offer "record from
      the start" for streams with an end, and refuse to start a 24/7 stream that
      would fill the disk.
- [ ] **A playlist becomes real rows.** Today 183 videos are one row: one
      progress bar resetting 183 times, no per-video retry or cancel, serial
      despite "Downloads at once", one history entry, Show in Finder pointing at
      the last file. The flat entry list is already fetched.

## Phase 4 — YouTube keeps working

- [ ] **Proof-of-Origin tokens.** YouTube expects them in 2026; yt-dlp's wiki
      recommends a provider plugin. bgutil runs on Deno ≥ 2.0, which Lasso
      already bundles. *Done when:* the provider is pinned in
      `binaries.lock.json`, loaded through an explicit `--plugin-dirs`, and a
      real YouTube download succeeds with it from a flagged network.
- [ ] **Bot check as a doctor check**, with the fix it needs.

## Phase 5 — The redesign

The UX audit's diagnosis: Lasso kept Webflow's restraint and dropped its
boldness — the largest type in the app is 20 px and colour appears only as
6 px dots. The proposal uses more of `DESIGN-webflow.md`, not less.

- [ ] Display type tokens (24 / 32 px) and a heading on every screen.
- [ ] **Ready:** one job on screen — paste — with recent downloads and their
      thumbnails instead of an empty queue pane.
- [ ] **Choose:** Video or Audio as the system's full-colour category cards;
      one quality list with honest sizes; presets become "Saved choices";
      the button says what you get ("Download · 1.4 GB").
- [ ] **Downloading:** the active download as the focus, with total size,
      speed and time left; playlist groups; errors inline with their fix;
      labelled Open / Show in Finder.
- [ ] **History:** thumbnails, dates, search.
- [ ] **Settings:** preferences separate from "About & diagnostics"; helper
      versions out of the way; "Select" becomes "Automatic".
- [ ] Jargon pass: no "27 formats", "best", yt-dlp version in the title bar.
- [ ] CLAUDE.md's "Two-pane window" and "Compressed density" decisions updated
      to match.

## Phase 6 — Links from anywhere

- [ ] Drop a link on the window or the Dock icon.
- [ ] `lasso://` links, so a bookmarklet or Shortcut can hand Lasso a URL.
- [ ] ⌘, opens Settings; File menu with Paste Link and Download.
- [ ] Dock badge with the active count.

## Phase 7 — Trust and reach

- [ ] **Signed releases.** Today every install is protected only by the GitHub
      account. Sign `latest.json` with ed25519 and embed the public key, as
      Sparkle does. *Decision needed:* where the private key lives.
- [ ] **Verify yt-dlp's own signature.** yt-dlp publishes `SHA2-256SUMS.sig`;
      Lasso ignores it.
- [ ] **Intel Macs** cannot launch Lasso (arm64 only). *Decision needed:* a
      universal build, or a separate Intel download.

## Phase 8 — Ship 0.2.0

- [ ] End-to-end pass in the real app, every screen, on a regular desktop Space.
- [ ] README updated for the new flow.
- [ ] `make release-assets NOTES=…`, staged publish, both discovery paths checked.

---

## Decisions

- **Adopted:** the redesign direction in the mockup, which replaces CLAUDE.md's
  "Two-pane window" and "Compressed density" rules (Phase 5).
- **Open, asked when reached:** release-signing key custody (Phase 7); Intel
  scope (Phase 7); notarisation, which needs the paid Apple Developer Program.
